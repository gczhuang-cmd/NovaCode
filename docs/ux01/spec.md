# UX01：流式期间实时反馈 Spec

> 本次为独立体验优化，与功能章节 chXX 区分；文档路径 `docs/ux01/`。

## 背景

NovaCode 主循环流式渲染时（`llm/openai_provider.py`）：

- **只取 `delta.content`（正文）**，把 `delta.reasoning_content`（模型思考内容）整个丢弃；
- 把 `delta.tool_calls[].arguments`（工具参数）拼接进 buffer，直到整个流结束才一次性上抛。

实测（deepseek-v4-flash，`_probe_deepseek.py`）证明：一次简单数学提问，698 个输出 token 中 **436 个（62%）是思考 token**（`usage.completion_tokens_details.reasoning_tokens`）。思考内容可流式获取、占比极大。

结果：模型「思考」和「生成大工具参数」期间，UI 无任何实时内容，只剩「思考中…(Ns)」跳秒。用户在用 frontend-design skill 开发的会话里观察到：写 `shop.css` 前静默 **213 秒**、`shop.js` 前 **18 秒**，中间两次审批间隔「像卡住一样」。

ch02 曾明确约束「思考增量接收即丢弃，界面不出现任何思考文本」（`docs/ch02/spec.md` AC5）。**本次推翻该约束**，改为实时反馈。

## 目标

- **推理段**：Live 动态区实时滚动展示思考内容（最近 N 行），Ctrl+O 切换显示完整思考。
- **生成段**：工具参数生成期间，Live 动态区实时显示字符进度。
- 思考/工具进度内容**不进对话历史**、不进会话存档、不参与后续请求——纯展示用。

## 功能需求

- **F1 推理段实时滚动**：流式期间收到思考增量时，Live 动态区实时滚动展示思考内容，只保留最近 **N 行**（N 默认 3）。
- **F2 Ctrl+O 展开/折叠**：推理段按 Ctrl+O 切换为「显示完整思考内容」，再按恢复「最近 N 行」；展开态下思考内容继续随增量增长。
- **F3 阶段让位**：推理结束后（进入正文或工具参数阶段），Live 区让位给正文打字机 / 工具参数进度，思考内容不再显示、不写入 scrollback、不进入对话历史。
- **F4 生成段字符进度**：工具调用参数增量到达期间，Live 区显示「正在生成 `X` 参数…(已 N 字符)」，字符数随增量实时增长；多工具并发时逐行展示。
- **F5 工具执行不受影响**：工具调用仍以完整参数执行（增量仅用于展示）；审批时机、工具行为与改动前一致。
- **F6 思考不进任何持久化**：`reasoning_content` 不混入正文流、不进入对话历史与 JSONL 会话存档、不回灌给后续请求。
- **F7 完成后本轮思考统计**：回复完成时，扩展现有「用时」行，附本轮思考 token 数（流末尾真实 `reasoning_tokens`），如「· 用时 213s · 思考 436 tokens」；**不显示 in/out**（会话累计 in/out 已由状态栏承担，避免信息重复）。本次涉及的 token 显示统一用全称 **tokens**。

## 非功能需求

- **N1 展示不阻塞主流程**：思考/进度的渲染失败或异常不影响正文、工具执行与审批。
- **N2 渲染频率**：随模型流式增量自然更新，不额外加节流；Live 更新成本可控（见 N4）。
- **N3 平台兼容**：Ctrl+O 在 Windows（msvcrt）与 Linux（termios 半 raw）都能捕获，且不影响现有 Esc/Ctrl+C 取消。
- **N4 性能**：思考可能很长（数十 KB），「保留最近 N 行」需避免逐字符 O(n²) 拼接；完整思考的展开展示应可承载长文本。
- **N5 不破坏现有功能**：本次改动不改变 JSONL 会话存档格式与字段；思考内容与工具参数增量不落盘，`/resume` 恢复历史对话的解析、展示与继续对话行为与改动前一致；状态栏累计 in/out 展示不受影响。

## 不做的事

- 不做思考内容的精确 token 计数展示（`usage.reasoning_tokens` 可选作进度补充，非必须）。
- 不做工具参数内容滚动展示（已定「字符进度式」）。
- 不做思考内容的持久化 / 回看 / 存档。
- 不改 anthropic 协议适配器的思考展示（其 thinking_delta 有回灌签名约束，留后续）。
- 不改变审批交互本身。

## 验收标准

- **AC1**：真实对话触发推理时，Live 区实时滚动思考内容，且仅保留最近 N 行（N=3）。
- **AC2**：推理段按 Ctrl+O 展开显示完整思考内容，再按恢复最近 N 行；展开期间思考内容继续增长。
- **AC3**：推理结束后正文打字机正常接管，Live 区无思考残留。
- **AC4**：模型生成大工具参数（如 write_file）时，Live 区显示「正在生成 X 参数…(已 N 字符)」且字符数增长。
- **AC5**：工具执行与审批行为与改动前一致（增量仅用于展示）。
- **AC6**：会话 JSONL 中无 `reasoning_content` 与工具参数增量记录；后续请求不回灌思考内容。
- **AC7**：Esc / Ctrl+C 取消仍正常工作，Ctrl+O 不干扰现有取消逻辑。
- **AC8**：`/resume` 恢复历史会话后对话正常继续，无异常内容或解析错误；会话 JSONL 字段与改动前一致（无 `reasoning_content` 落盘）；状态栏累计 in/out 与完成统计行语义不重叠。
